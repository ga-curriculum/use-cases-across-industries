The Customer Insight Analyzer

Acme SaaS has 50,000 customers and a support team drowning in tickets. Every quarter, the Product team spends three weeks manually reading Zendesk tickets, App Store reviews, and Salesforce CRM notes to produce a Customer Insight Report — a document that shapes the next quarter's roadmap.

The process is slow, inconsistent, and expensive. Important signals get missed. The Product team suspects there are patterns in the noise — recurring complaints, emerging feature requests, churn predictors — that no human has the bandwidth to surface at scale.

They want an autonomous agent that ingests all three data sources continuously, identifies patterns, generates strategic insights, and delivers a structured report to the product leadership team every Monday morning — with no manual intervention.
Primary Goal
Produce a weekly Customer Insight Report containing the top 5 emerging themes, top 3 churn risk signals, and the top 2 feature requests — ranked by frequency and sentiment intensity — without any human labor in the loop.

Success Criteria
✓ Report delivered every Monday before 8:00 AM
✓ Each insight is backed by a minimum of 3 source citations
✓ Sentiment scoring is consistent week-over-week
✓ No PII (personally identifiable information) included in the final report
✓ Product team spends less than 10 minutes reviewing — not rewriting

Why an Agent (not a script)?
A script could pull data. An agent can reason about it — classifying, comparing to prior weeks, surfacing non-obvious connections, and adjusting its analysis when data quality is poor.
Data Source 1 — Zendesk (Support Tickets)
~2,000 new tickets per week. Plain text, tagged by category. Contains customer language, frustration signals, and unstructured feature requests. Requires API authentication.

Data Source 2 — App Store Reviews
~300 new reviews per week across iOS and Android. Public data — no auth required. Contains star ratings + free-text commentary. High signal-to-noise ratio for product quality perception.

Data Source 3 — Salesforce CRM Notes
Customer success rep call notes from ~150 accounts per week. Highly valuable but inconsistently formatted — some reps write paragraphs, others write bullet points or nothing at all. Requires Salesforce API connector with OAuth.

Total weekly input volume: ~2,450 documents · ~1.2M tokens before chunking.
Privacy Constraint
No customer names, email addresses, or account IDs may appear in the final report. The agent must strip or anonymize PII at the data ingestion stage.

Reliability Constraint
If fewer than 500 tickets are retrieved in a week (indicating an API failure), the agent must not generate a report. It should flag the error and notify the ops team.

Cost Constraint
The total LLM cost per weekly run must stay under $4.00. This forces the agent to use chunking and summarization strategies rather than passing raw full-text to the LLM.

Consistency Constraint
The agent must compare this week's insights against the prior 4 weeks to distinguish "new signal" from "persistent issue." This requires persistent memory across runs.
📌 Before moving on: Make sure you've read all four panels. The constraints panel in particular directly shapes which tools, memory types, and reasoning steps the agent needs.
